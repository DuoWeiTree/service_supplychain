## 1. 读什么

每一张**未作废**的领星备货单（`ext_ref` 无 `ext_ref_void`），只要它所在排货单是 `已投送`（还没归档），就用 `ows_order_detail`（`/basicOpen/overSeaWarehouse/stockOrder/detail`，已登记）读一次。

★ 只读领星，不碰 CH（AR-D1）。CH 的 `lingxing_warehouse_oversea_stock_list` 实测最新采集 10-09，10-12 建的单一张没有。

## 2. 领星状态 → 领星进度（`04` §4.4，领星自己的词）

| `status` | 领星进度 | rank | 说明 |
|---|---|---|---|
| 10 | 待审核 | 1 | |
| 30 | 待配货 | 2 | |
| 40 | 待发货 | 3 | 我们建单就是 40（CB-D2） |
| 50 | 待收货 | 4 | `sub_status` 原样留在观察里（`04` 陷阱①：部分收货靠它分） |
| 60 | 已完成 | 5 | |
| 20 | 已驳回 | 旁路 −1 | 非前进终态 |
| 51 | 已撤销 | 旁路 −1 | 非前进终态（`04` §4.4 表） |
| 详情答「不存在或已删除」 | 领星无此单 | 旁路 −1 | 有人在领星直接删了 |
| 其他值 | —— | 不写观察 | 记日志点名 `unknown_status`，★ 不猜 |

当前进度 = 有旁路观察取最新的那条旁路，否则取 rank 最大的那条（`03` §5 视图口径：★ 结构上不会倒退，倒退的读回照写但不改当前进度）。

## 3. 落表（迁移 `023`）

| 表 | 列 | 性质 |
|---|---|---|
| `ext_stage_obs` | `obs_id` · `ext_ref_id` · `observed_at` · `status`（领星原值）· `stage` · `stage_rank` · `sub_status` · `detail`（发货 / 到达 / 签收时间、物流单号等原样）· `run_id` | ★ 只追加 |
| `receipt_run` | `run_id` · `trigger`（`scheduler` / `manual`）· `actor`（手动时）· `started_at` · `finished_at` · `refs` · `ok` · `failed` · `failures`（每张失败的单号 + outcome + cause） | ★ 只追加；一轮一行 —— 「读了几张、失败几张、是谁」可查（`01` 采集面留痕） |
| 视图 `v_ext_stage` | 每个 `ext_ref` 的当前进度 · rank · 最后观察时刻 | 派生，不存 |

## 4. 观察带来的动作

| 情况 | 动作 | 出处 |
|---|---|---|
| 一张排货单的**全部**未作废领星单都 `已完成` | 排货单 `已投送 → 已归档`（同一事务，库层再核：触发器 `consignment_archive_needs_complete`） | `04` S4 #16 |
| 领星 = 已驳回 / 已撤销 / 无此单，而我方 = 已投送 | ★ **不自动改我方状态**；排货表页与接口点名「两轴不一致」 | `04` §4.5 |
| 读失败（连不上 / 超时 / 被拒） | 不写观察、不改状态；`receipt_run.failures` 点名 + 日志三问 | CLAUDE.md 出站 #5 |

## 5. 什么时候读

| 触发 | 范围 | 频率 |
|---|---|---|
| 定时（`jobs/scheduler.py` 新 job `receipt_tick`） | 全部「已投送」排货单的未作废领星单 | 每 30 分钟 · ★ 设计取值 · 未实测（`service.toml` 可配） |
| 手动：排货表页打开即现查 + 每张单「重新读回」（10-13 负责人，同采购单 PB-D27） | 这张表的 | 即时 |

两种触发都持 `sheet_op` 锁逐表读（与提交 / 取消 / 退回互斥）；拿不到锁的表本轮跳过并记入 `receipt_run`（不是失败）。

## 6. 接口（`08` §1.3）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/sheets/{id}` | `ext_refs[]` 每张带 `erp_stage`（领星进度；L8：前端不出现领星英文名） · `stage_observed_at` · `drift`（两轴不一致的原因，无则 null） |
| POST | `/v1/sheets/{id}/receipt` | 现查领星状态；返回每张的结果（新进度 / 失败原因）与归档了哪些排货单 |

## 7. 界面（`10` §2.0b）

排货单面板每张领星单一行：单号 · 来源仓 · 两轴「本地 | 领星 进度 读回于 时刻」+「重新读回」· 这一张没读到 / 读回请求失败分别点名（显示的是上次观察）· 两轴不一致时醒目点名；排货单 `已归档` 显示在排货单头上；底部排货单 chip 带领星进度。有未作废领星单的表打开即现查一次（10-13 负责人：「需要有类似采购单一样的状态回读小按钮」）。

## 8. 测试（先红）

| 层 | 用例 |
|---|---|
| 纯 | status → 进度映射；未知值不写；当前进度取法（旁路优先、rank 最大、倒退不影响） |
| DDL | 观察 / 轮次只追加；归档前置（有一张没完成 → `consignment_archive_needs_complete`） |
| API | 现查：40 → 50 → 60 逐次读回，第三次后排货单归档；一张完成一张没完成不归档；领星删单 → drift 点名、我方不变；读失败 → run 记失败、无观察；与提交互斥 `sheet_busy` |
| 作业 | `receipt_tick` 只读「已投送」的单、不读草稿 / 已确认 / 已归档；一张失败不拖累其余 |
| Web | 进度显示、drift 点名、打开即现查 · 逐张「重新读回」· 失败逐张点名 |
