## 1. 要解决的事

运营在计划里填两个数：**期望销量**（msku × 月）和**计划采购**（货号 × 月）（`02` §3.1b）。
为了填对，他要在同一格里看到：

1. **预测销量** —— 历史推出来的「这个月大概卖多少」，是期望销量的默认值；
2. **库存** —— 扣掉期望销量、加上到货之后，这个月月底还剩多少，以及它怎么影响后面的月份。

现状两样都不成立：系统预估是把历史月销量**按位置搬过来**（10 月 = 6 月实际），
库存只减不加、计划采购一件都不进。

## 2. 格子里的四种数 —— 不许混

| 数 | 粒度 | 谁给 | 对库存的作用 | 出处 |
|---|---|---|---|---|
| ★ **计划采购** | 货号 × 月 | 运营填 | **加**：下单月 15 号 + 生产 + 货运 之后到货 | `02` §3.1b · `14` §2 |
| ★ **期望销量** | msku × 月 | 运营填，默认 = 预测销量 | **减**当月 | `02` §3.1b · `prompt.md` 第 3 条 |
| **预测销量** | msku × 月 | 系统算（历史） | ★ **不直接进库存** —— 进库存的是期望销量 | `02` §3.1b「扣的是期望销量，不是系统预估」 |
| **库存** | msku × 月（期初 / 期末）· 货号级在途 | 系统算 | —— | `14` §0 · `02` §3.1a |

★ 库存分两类（`02` §3.1a · `14` §1）：

| | 是什么 | 进不进可售 |
|---|---|---|
| **可售库存** | FBA 在仓（msku 级，`afn_fulfillable_quantity`）+ 已到货的计划采购 | ✓ |
| **在途** | 货号级：计划采购在管道里（生产中 + 货运中）+ 领星已下单未到货 | ✗ —— 到货那天才转成可售 |

## 3. 预测销量（UC-F1）

### 3.1 算法：按 `00` D-3 已裁定的「先搬（绿）再修（红）」

★ 在本仓**重新实现**成纯函数（`01`「预测只是它内部的一个纯函数」），不调用兄弟仓、不读 `inv.*`。
算法照搬兄弟仓 v1 `baseline_rate`（`17` §「预测模型」表 v1 行）：

```
base_rate[msku, sid] = 近 56 天日销
                        → densify（没出现的日子 = 卖了 0，从该 msku 首次有销量那天起）
                        → censor（剔掉 FBA 可售 ≤ 0 的日子：那天的 0 是没货，不是没需求）
                        → 截到非零日的 p95
                        → 指数加权算术均值（半衰期 14 天）
                        → 向自身近 90 天算术日均收缩，权重 n/(n+3)
预测销量[msku, 月] = base_rate × 该月天数          （季节指数停用，与 v1 同）
```

常数（56 / 14 / 90 / 3 / p95）全部来自兄弟仓 `demand.py:67-77`，**不另调**。

| 步 | 做什么 | 门禁 |
|---|---|---|
| **① 搬（绿）** | 搬 `models/inventory_forecast/tests/fixtures/` 的 9 个 CSV 与 `test_recon.py` 的 228 格期望值 | ★ 必须一次绿 —— 红了就是搬错了，且能定位到格 |
| **② 修（红）** | 订单滞后采集 → 近几天不完整 → 指数加权把最高权重压在最不完整的那几天 → 系统性低估约 23%（`06` §4） | ★ 门禁必然变红，再用当前数据跟运营对新基准 |

★ 第 ② 步的修法：**估计锚点从 as_of 往前挪 `embargo_days` 天**（整个窗口后移，不丢样本），
取兄弟仓 v2 的做法（`maturity.py:179`）。`embargo_days = 7` —— ★ **设计取值 · 未实测**：
兄弟仓自己标的是占位（实测成熟度曲线 age≥7 才 100%，但那批数据受 08-20 回填污染）。记 `00` W-5。

### 3.2 输入

| | 来源 | 粒度 |
|---|---|---|
| 日销 | CH `amazon_sp_api_report_all_orders`，按 order_item 去重（已有的 `SQL_MONTHLY_SALES` 口径，改成按日） | msku × sid × 日 |
| 断货日（censor） | CH `lingxing_inventory_fba_detail` 各 `_captured_date` 的 `afn_fulfillable_quantity ≤ 0` | msku × sid × 日 |

### 3.3 输出与依据

- 每格一个**整数**（`prompt.md` 第 3 条），取整规则 = 向上取整（`17` 表：`system_value` 向上取整）。
- ★ 依据随数一起存（`14` §6）：`base_rate`、该月天数、估计锚点、`embargo_days`、窗口起止、
  censor 掉几天、收缩前后的两个速率。界面点开能看到「预测 124 = 4.13 件/天 × 30 天」。
- 没有历史 ≠ 0：`system_units` 留 NULL 并点名（现有行为不变）。
- ★ `system_extrapolated`：速率模型对任何一个月都算得出，没有「覆盖不到」的月份，所以不再产生外推。
  标记列保留（M-13），**由算法如实给 false**，不是盖章。

### 3.4 什么时候算

认领 msku 时算一次并 seed 进格子（现有时机，`07` 时序）。依据一起落 `plan_demand_cell.system_basis`（新列）。
★ 重算时机未定 —— 记 `00` W-7。

## 4. 预测库存（UC-F2）—— 梦倩的逐日台账，按我们的口径

### 4.1 台账（`formulas.md` §一 · `ledger.py`）

每个 msku（有 FBA 的店铺）从 as_of 那天收盘起，**一天一天往下记账**：

```
今天可售 = max(0, 昨天可售 + 今天到货 − 今天卖掉)        ← available（lost_sales）
今天卖不出去 = max(0, 今天卖掉 − 昨天可售 − 今天到货)      ← daily_unmet
带符号头寸 = 期初 + Σ到货 − Σ卖掉                         ← signed_position（不截断）

★ 恒等式：带符号头寸 ≡ 可售 − 累计卖不出去                 （每轮断言）
```

### 4.2 每天卖多少

- ★ 用**期望销量**（人改过的以人为准），不是预测销量（`02` §3.1b）。
- 月度数摊到每天：**半月均分**（15 号累计正好一半，与 `14` §2.3 的 15 号锚一致；`formulas.md` §3.3 第一种）。
  ★ 摊分不改月总数：`Σ当月每日 ≡ 期望销量[月]`（构造保证，断言）。
- ★ **as_of 到计划首月之间的那几天**（例：as_of 9/22，计划从 10 月起）也在消耗库存，
  但计划里没有这几天的期望销量。建议按**预测销量**扣，并在依据里单列「9/23–9/30 按预测扣 N 件」。
  ★ 这是我的建议，不是已有裁定 —— 记 `00` W-6。不扣的后果：10 月期初系统性偏高。
- 期望销量为空 → 这个 msku 从该月起库存**未知**，向后传染，不当 0（`14` B1/B2）。

### 4.3 每天到多少货

| 来源 | 什么时候到 | 进可售？ |
|---|---|---|
| ★ **计划采购**（货号级） | 下单月 15 号 + `make_days` → 完工；再 + `ship_days` → 到货（`14` §2.1~§2.3） | ✓ 到货当天，按 §4.4 分给各 msku |
| 领星已下单未到（CH 采购单 `status=2`） | ★ **不定到货日**（98.8% 已过预计日，chsource OQ-6：不许悄悄挪月） | ✗ 只计入货号行的「在途·已下单」 |
| FBA 货件已发未到（`入库·已确认`，`14` §4） | 阶段 A 未取数 | ★ 显示「未取」，不显示 0 |
| 本地仓在库 | —— | ✗（`14` B6） |

到货落在计划周期之外的采购**逐笔列出**（`14` B3），不悄悄丢。

### 4.4 到货给哪个 msku（`14` §3 两遍法）

```
第一遍 · 基线：不补货，各 msku 逐月累计缺口 G
第二遍 · 按到货日从早到晚逐批分：
    谁都不缺     → 全部按期望销量比例摊
    缺口 ≤ 这批  → 先补齐缺口，余量按期望销量摊
    缺口 > 这批  → 按缺口比例，取整，余数给缺口最大的
★ 断言：Σ分到的 ≡ 这批件数
```

★ 这是**预测**不是排货：不写任何表、不产生动作，依据如实记录实际怎么分的（`14` §3.2 · §3.3）。

提前期（`03` §41 `lead_time` · 负责人 09-24）：

| 变量 | 默认 | 谁改 |
|---|---|---|
| `make_days` 生产 | **30** | 用户（全局配置，界面可改，改完立即重算 —— `14` B12） |
| `ship_days` 货运 | **60**（国际海运） | 同上 |
| 锚点 | 下单月 **15 号** | 不开放（`14` §2.3 · M-12） |

### 4.5 ★ 按月读出：期初、期末逐月相接

```
期初[首月] = as_of 当天 FBA 可售 − as_of 到首月前一天的消耗（§4.2）
期末[m]   = 期初[m] − 期望销量[m] + 当期入库[m]        ← 带符号，负数照实显示（`14` B8）
期初[m+1] ≡ 期末[m]                                     ← 恒等式 ④（`14` §1.1），测试钉住
```

例（负责人 09-24）：10 月期望 100，期初 200 → 期末 100 → 11 月期初 100。

另给**预计断货日**：逐日台账里第一个 `daily_unmet > 0` 的日子。
★ 月末「期末」用带符号头寸（= 负责人 Excel），断货日用截断台账 —— 两者由 §4.1 恒等式连着，不是两套数。

### 4.6 汇总（`14` §1.1 ①：合计行不许独立算一遍）

| 行 | 期望 | 预测 | 库存（期末） | 在途 |
|---|---|---|---|---|
| msku | 自己 | 自己 | 自己 | —— |
| 店铺 | Σ msku | Σ msku | Σ msku | —— |
| 货号 | Σ 店铺 | Σ 店铺 | Σ 店铺 | 管道（生产中 + 货运中）+ 已下单未到 |

- 任一 msku 未知 → 上一层未知（`14` B2）。
- 无 FBA 的店铺 → 「不适用」，不进求和，不当 0（`02` §3.1a）。

| 行 | 主数 | 副数（文字标签，不只靠颜色） |

点开一格看依据：

```
库存 · A4Pet-US · MSKU-A · 2026-10
  期初 200（= 9 月末；as_of 09-22 可售 230 − 9/23–9/30 按预测扣 30）

  + 到货 0
  = 期末 100   → 11 月期初
预测 · 124 = 4.13 件/天 × 30 天（窗口 07-28 ~ 09-15，禁言 7 天，剔断货 3 天）
```
