## 1. 一句话

运营在销售计划里提交「某货号、某月要采购多少件」（**计划记录**）。采购员把若干条记录按供应商组成**采购单**，
填好仓、单价、预计到货，⛔ **下单**：系统在领星 ERP 里建出一张真实采购单（**不可撤销**），
之后随时从领星**读回**它的最新状态，并核对领星里的明细与我们发出去的是否一致。

```
销售计划（运营）──提交──▶ 计划记录（货号 × 月 × 总量，按店拆有期望销量）
                                   │  采购员勾选、组单（来源 = 记录 × 店 × 件数）
                                   ▼
                             采购单 草稿 ──⛔ 下单──▶ 领星采购单（待到货 …）
                                   │                       │
                                   └──── 读回 / 核对 ◀─────┘
```

## 2. 对象与关系（设计时要分清的几样东西）

| 层 | 东西 | 说明 |
|---|---|---|
| 对象 | **计划记录** `plan_line` | 计划 · rev（版本）· 货号 · 月份 · 总量 · 各店期望销量。状态见 §3.3 |
| 对象 | **采购单** `po` | 本系统的单：单号 `SCM-PO-{id}`（也是发给领星的幂等键 `custom_order_sn`）· 供应商 · 采购方 · 采购员 · 质检方式 · **一个仓** · 若干明细 |
| 对象 | **明细行** `po_line` | 货号 · 数量 · 单价 · 预计到货 ·（超出计划的部分）理由。领星建单后回填**领星行号** |
| 关系 | **来源** `po_source_map` | 明细行 ← 计划记录 × 店 × 件数。一行可有多条来源；记录 → 采购单是 1:N（一条记录可分几张单组完） |
| 对象（外部） | **领星采购单** | 领星单号 `PO2610…`、领星状态、到货状态、领星明细。★ 只读回，不在本系统改 |
| 状态·事实 | 已组单量 / 已下单量 / 还可组 | 由来源和单的状态**推导**，不是人填的 |
| 状态·事实 | 领星观察 `po_snapshot` / `po_item_obs` | 每次读回追加一条，带「何时读的」 |
| 动作 | 组单 · 保存 · 下单 · 读回 · 重新核对 · 登记已有单 · 确认领星无此单 · 确认知悉 · 删除草稿 | 每个动作都留谁 · 何时 ·（需要时）理由 |

关键关系的量语义：

- **记录 → 采购单（1:N，可求和）**：一条记录的已组单量 = 所有未作废采购单里它作为来源的件数之和，**不能超过记录总量**。
- **来源记到店铺**，但**没有分店上限**（PB-D22）：一家店可以拿满整条记录。店只能选该记录里出现的店。
- **超计划量允许**（PB-D9）：明细数量 > 来源合计时，多出的部分是「无计划来源」，**必须写理由**。

## 3. 状态

### 3.1 采购单 · 本地状态（我们写）

| 状态 | 含义 | 能做的事 |
|---|---|---|
| 草稿 | 还没成功下到领星 | 改 · 删 · 下单 |
| 草稿（已作废） | 试过下单的草稿被删除时**不硬删**：单头留档、额度释放 | 只读 |
| 已下单 | 领星已建单，单号已记下 | 只读；读回；处理不一致 |

### 3.2 采购单 · 领星状态（只读回，★ 与本地状态**并排显示，不合成**）

| 领星 `status` | 文案 | | 到货 `status_shipped` | 文案 |
|---|---|---|---|---|
| -1 | 作废 | | 1 | 未到货 |
| 3 | 待提交 | | 2 | 部分到货 |
| 1 | 待下单 | | 3 | 全部到货 |
| 2 | 待到货 | | | |
| 9 | 完成 | | | |
| 121 / 122 / 124 | 审批流待审核 / 驳回 / 作废 | | | |

- 码表出自领星 `PurchaseOrderList` 文档；**认不出的码原样写「状态码 N」，不猜**。
- 从没读回过 → 「未读回」；草稿 → 「未下单」。读回总带**读回时间**（陈旧数据要标注）。
- 领星侧作废（-1）被读回后：该单不再占计划额度，计划记录状态随之退回（PB-D5）。

### 3.3 计划记录的采购状态（由量推导，人不能直接改）

| 状态 | 判据 |
|---|---|
| 已提交 | 还没组满（可组单） |
| 已确认 | 已组单量 = 总量（可组单 —— 仍可被改单释放） |
| 已下单 | 已下单量 = 总量 |
| 已撤销 / 已完结 … | 不可组单（在待采购清单里**折叠计数**，不隐藏） |

### 3.4 需要人工处理（三类，顶栏红条常驻提示）

| 类型 | 何时出现 | 出口（动作） |
|---|---|---|
| **下单结果待核实** `needs_verify` | 下单请求发出去了但没拿到明确结果（超时、连接中断），按幂等键也没查到 | **重新核对** · **登记已有单**（填领星单号，对得上才接受）· **确认领星无此单**（理由必填，解锁改 / 删 / 再下单） |
| **领星明细不一致** `landed_mismatch` | 读回发现领星里的明细与我们发的不符；或同一幂等键下有多张单 | 只能去领星处理（PB-D16）：改成一致后重新核对，或在领星作废；已下单的单可 **确认知悉**（理由必填，不改任何单） |
| **下单请求卡住** `stuck_call` | 下单调用在途超过 10 分钟（设计取值） | 等系统恢复流程按幂等键查重；页面只陈述，不给按钮 |

★ 有未处理项时，后端拒绝改 / 删 / 下单（409）。所以有未处理项的草稿**不进编辑器**，进详情页处理（§5.2）。

## 4. 端到端任务流（采购员视角）

```
① 采购首页「待采购」 勾选几条记录 → 用选中的 N 条建采购单
② 编辑器：选供应商 / 采购方 / 采购员 / 质检方式
          左栏是带来的记录：逐店填件数「加入」→ 右栏按货号生成明细
          每行选仓（全单必须同一个仓）、填单价、预计到货；超计划量写理由
          下方「下单前检查」实时列出每一道闸过没过
③ 保存草稿（可选）或直接 ⛔ 保存并下单
④ 确认弹窗：列出将要发给领星的完整内容（供应商、采购方、采购员、质检、幂等键、逐行货号/仓/数量/单价、合计件数与金额）
          ⛔ 确认下单
⑤ 结果四种：
   · 已下单 → 提示领星单号，进详情
   · 领星拒绝 → 弹窗里显示领星原话；授权类（code 403）明说「改草稿没用，要管理员开权限」
   · 没发出 → 可直接再下单
   · 结果未知 → 关掉确认、不许再点，每 3 秒查调用记录直到有结论；仍不明 → 转「待核实」
⑥ 详情页：打开即向领星读回最新状态；可「重新读回」；读回同时做落地核对，不一致自动开待处理
```

## 5. 页面逐个说明（现状）

> 路由在 `web/src/routes.tsx`；所有页面共用 `AppShell`，顶部有**全局待处理红条**（`AttentionBanner`，数据 `GET /v1/attention`）。

### 5.1 采购首页 `/purchase`（`PurchaseHome`）

自上而下（PB-D19：待采购在最上面）：

1. **待采购**（`GET /v1/plan-lines?orderable=1`）
   - 每行：勾选 · 计划名（链到计划页）· rev · 货号 · 月份 · 总量 · **还可组** · 各店「期望 N（占比 x%）已组 M」
   - 期望为空的店写「未知」，**不是 0**，记录照样能勾（PB-D22 起不再有「无分店依据」挡单）
   - 「未列入 N 条」折叠：只数已组满；★ 不显示「状态不可组单」（旧版被替换 / 已完结的历史，PB-D29）
   - 按钮 **用选中的 N 条建采购单** → `/purchase/new?lines=…`（按清单顺序带过去）
   - 店名取不到时按店编号显示并说明
2. **需要人工处理**队列（按类型分组，点「打开」进该单详情）
3. 计数条：草稿 N · 已下单 N · 核对结果（`GET /v1/checks/purchase`：「核对全部通过」，否则违例明细在折叠区「不一致明细」）
4. **采购单**表（`GET /v1/purchase-orders`）：单号 · 供应商 · 状态 · 领星单号 · 行 · 件数 · 待处理 · 建单人；按钮 **新建采购单**
   - ⚠ 列表**没有领星状态**（列表接口不带，读回只在详情页按需做）

各区块各读各的接口、各报各的错：一个挂了其余照常显示。

### 5.2 `/purchase/:poId` 的分发（`PoRoute`）

只有「草稿 · 未作废 · 无未处理项 · 无卡住 / 在途的下单调用」进**编辑器**，其余进**详情**。
判断要三样数据都在手（单、待处理队列、调用记录）；任何一样取不到 → 进详情（**失败即关闭**，不赌它可编辑）。

### 5.3 编辑器 `/purchase/new` · `/purchase/:poId`（`PoEditor`）

**单头**：供应商（下拉，来自供应商镜像）· 采购方 / 采购员（下拉 + 「手填」；来自领星历史的选项标出处与次数；领星历史取不到时写「领星历史暂不可用」，原因折叠）· 质检方式（仓库质检 / 预检 / 免检）。

**左栏 · 可组单记录**（按货号分组）
- 带 `?lines=` 进来时只列带来的记录，顶部写「来自 销售计划「X」revN 的 N 条记录」；**加入其他待采购记录** 展开全部
- 带来的记录列不出（已组满 / 状态变了 / 不存在）→ 逐条反查并点名原因
- 每条记录：计划名 rev 月份 · **剩 余量/总量**（记录级，扣掉本稿已加的、加回本单已保存的）
- 每店一行：店名 · 期望（参考，空写未知）· 件数输入 · **加入**
  - 拒绝时就地写原因：超过该记录剩余（最多还能加 N）· 这家店不在该记录里 · 数量要是正整数
  - 记录剩 0 → 加入禁用，写「已无剩余」
- 「本单原有来源」：本单把某条记录组满后候选里不再列它，单独列出，只能加回本单原有的量

**右栏 · 明细**（每个货号一行；「加入」落到该货号的第一行，见 §9 PB-U8）
- 仓（下拉）· 数量（默认 = 来源合计；改大出现「无计划来源 N 件」+ 理由输入；改小于来源合计报红）· 单价 · 预计到货
- 来源链逐条：「计划名 revN 货号 月份 → 店 N 件」+ 移除
- 数量填小数 / 负数：不截断，写「数量要是非负整数，未采用」

**下单前检查**：所有闸一次列全、逐条过 / 未过（闸表见 §7）。有改动时用本地校验，已保存且无改动时用后端检查。

**按钮**：保存草稿 · 删除草稿（二次确认，非危险样式）· 右侧分开的 ⛔ 按钮：
- 有未保存改动或新建 → **⛔ 保存并下单**（PB-D23）：先保存 → 等后端检查 → 全过才开确认弹窗；保存失败停在保存错误上，检查没过在按钮旁点名
- 已保存且无改动 → **⛔ 下单**；被挡时按钮旁写原因（正在检查… / 某闸 未过 / 下单前检查取不到）

### 5.4 ⛔ 下单确认弹窗（`PlaceDialog`）

- 标题「⛔ 下单到领星」，警示「这一步会在领星建出真实采购单，不可撤销」
- 打开时把单**冻结成快照**：屏上看到的就是要发出去的，确认 token 也是这一份的；期间草稿被别人改了 → 后端拒绝（`stale_confirm_token`），提示「草稿已变，请重新打开下单」
- 内容：供应商 · 采购方 · 采购员 · 质检方式 · 幂等键；逐行 货号 · 仓 · 数量 · 单价 · 其中无计划来源；合计件数、金额（精确求和，不经浮点）
- 结果区（弹窗不关）：
  - 领星拒绝（业务）：「领星拒绝了这张单，仍是草稿；改草稿后再下单」+ code · 打的哪个接口 + 领星原话（含 `error_details`，如「仓库不存在」）
  - 领星拒绝（授权，code 403，PB-D24）：「领星接口无权限或授权失效……改草稿没用 —— 请领星管理员在开放平台给本应用开通 / 续期该接口后再下单」
  - 没发出：「没有发到领星，可以再次下单」，原因折叠
  - 结果未知：「结果未知：不要再点，正在每 3 秒查一次调用记录」，确认按钮禁用，给「重新载入」
- 调用记录取不到时不许下单（下单后核对不了结果）

### 5.5 详情 `/purchase/:poId`（`PoDetail`）

- 头部：**本地状态 | 领星状态** 两轴并排 · 领星单号 · 幂等键 · 下单时间 · 供应商
- **领星状态**（PB-D27）：已下单的单**打开即现查领星**（只读），显示「待到货 · 部分到货 读回于 时间」+ **重新读回**
  - 读回中：「正在向领星查询…」（领星这个接口实测 1.6~10 s）
  - 这次失败：仍显示上次读回的状态与时间，写「这次读回失败（原因码），显示的是上次读回的状态」，原因折叠
  - 读回顺带做落地核对；核对出不一致 / 看到作废 → 整页重取（待处理项、额度会变）
- 明细表：行 · 货号 · 仓 · 数量 · 单价 · 无计划来源 · **领星行号**（未回填写明）· 来源（来源链 + 该记录的已确认 / 已下单量反查）
- 有待处理 / 卡住 / 在途下单时，顶部出现处理区（§5.6）
- 折叠区：状态记录（谁 · 何时 · 从什么到什么）、已处理项（谁 · 何时 · 理由）、全部调用记录（时间 · 人 · 接口 · 耗时 · 结果 · cause · 请求 / 响应）

### 5.6 处理区（`AttentionPanel`，「⛔ 需要人工处理」）

- 先写结论：**已知什么 · 不知道什么 · 最近一次查重（何时、结果、是否截断）· 怎么在领星里查**（幂等键 + 时间窗）
- 待核实：**重新核对** · 领星单号输入 + **登记已有单** · 理由输入 + **确认领星无此单**（理由空时按钮禁用）
  - 确认无此单被证据挡住时（`contradicts_evidence`）点名领星里已查到的单号
- 不一致：逐项对照表（项 · 我们 · 领星）；已下单的单可填理由 **确认知悉**；PB-D16 说明「只能去领星改对或作废」
- 下单进行中 / 卡住：只陈述开始时间，不给按钮，自动轮询直到落定

## 6. 业务规则（设计不能绕开）

| 规则 | 出处 |
|---|---|
| 一张单一个供应商 | spec §5 |
| 一张单只许**一个仓**（领星接口只有单头仓）；要发两个仓就建两张草稿 | PB-D25 |
| 同一张单里同货号只一行 | spec §5 |
| 组单只卡**记录总量**，没有分店上限；店只能选记录里的店 | PB-D22 |
| 超计划量允许，超出部分必须写理由 | PB-D9 |
| 下单不可逆；**超时一律转人工，绝不自动重试**（领星建单无客户侧幂等，重试就多一张真单） | CLAUDE.md 出站 #2 · PB-D13 |
| 幂等键 `SCM-PO-{po_id}`，调用前查重 | PB-V7 |
| 确认弹窗与 token 只认**已保存**的那一份；未保存改动由「保存并下单」先存 | H-1 · PB-D23 |
| 领星侧作废 → 释放额度、记录按量退回 | PB-D5 |
| 领星明细不一致不提供「接受差异」，只能去领星处理 | PB-D16 |
| 建单发系统 id（`sys_wid` / `sys_supplier_id`） | PB-D26 |
| 读回按 `order_sn[]` + 必填日期窗口；查重按 `custom_order_sn[]` | PB-D28 |
| 空 ≠ 0：期望销量为空写「未知」；没读回写「未读回」；入库量未接写 null 而不是 0 | CLAUDE.md 判据 |

## 7. 下单前检查（闸）

前后端同名；一次列全，不是遇到第一个就停。

| 闸 | 文案 | 过的条件 |
|---|---|---|
| `supplier` | 供应商 | 已选 |
| `purchaser` | 采购方 | 整数 |
| `opt_uid` | 采购员 | 整数 |
| `qc_type` | 质检方式 | 0 / 1 / 2 |
| `lines` | 至少一行明细 | ≥ 1 行 |
| `line_wid` | 第 n 行仓 | 已选 |
| `line_price` | 第 n 行单价 | 非负数 |
| `line_units` | 第 n 行数量不少于来源合计 | 数量 ≥ 来源合计 |
| `line_unplanned_reason` | 第 n 行无计划来源的理由 | 超计划时有理由 |
| `single_wid` | 全单同一个仓（领星一张单只能一个仓，分仓请建两张草稿） | 所有行同仓 |
| `sources_orderable` | 来源记录仍可组单 | 来源记录仍在 已提交 / 已确认（只有后端能判，点名不合格的记录与其状态） |

## 8. 接口速查（`api/ui/`，前端只许打这一层）

| 用途 | 接口 |
|---|---|
| 待采购 / 候选记录 | `GET /v1/plan-lines?orderable=1[&plan_ids=]` → `lines[]{line_id, plan_id, plan_title, rev, sku, period, total_units, remaining, state, sellers{sid:{expected, used}}}` · `excluded{state, fully_confirmed, …}` |

| 列表 | `GET /v1/purchase-orders[?state=]` |

| 建 / 改 / 删草稿 | `POST /v1/purchase-orders` · `PUT …/{id}`（带 `draft_version`）· `DELETE …/{id}` |
| 下单前检查 | `GET …/{id}/preflight` |
| ⛔ 下单 | `POST …/{id}/place {confirm_token}` → `placed` · `rejected{lx_code, lx_msg, rejected_kind: auth｜business, host, path}` · `not_sent` · `needs_verify` |

| 人工处理 | `POST …/{id}/recheck` · `…/register-existing {order_sn}` · `…/confirm-absent {reason}` · `…/acknowledge-mismatch {reason}` |
| 待处理队列 | `GET /v1/attention` |
| 核对 | `GET /v1/checks/purchase` |
| 记录反查 | `GET /v1/plan-lines/{line_id}/trace` |

常见错误码与它对用户的意思（完整表见 `08`）：

| 码 | 用户该知道的 |
|---|---|
| `over_total` | 超过记录总量（带总量 / 已用 / 本次） |
| `seller_not_in_line` | 这家店不在这条记录里（带允许的店） |
| `unplanned_reason_required` | 超计划的件数要写理由 |
| `duplicate_line` | 同货号同仓只能一行 |
| `stale_draft` | 草稿被别人改过，刷新后再改 |

| `preflight_failed` | 下单前检查没过（带没过的闸） |
| `needs_verify` / `po_placing` / `mismatch_open` / `po_frozen` | 这张单的状态在别处变了 → 回到按状态分发 |
| `unknown_supplier` / `unknown_seller` | 镜像里没有这个供应商 / 店 |

## 9. 已知缺口（设计时不要假设已经有）

| | |
|---|---|
| 采购单列表无领星状态 | 列表接口不带；只有详情页按需读回 |
| 未结单每日自动复核 | 未实现（PB-U11）；现在只有下单后首检 + 打开详情时读回 |
| 到货 / 收货 / 入库进度 | `GET …/progress` 属 M3，未实现；计划级采购完成度的入库列为 null |
| 作废但已有入库 | 不区分，读回作废即释放额度（PB-U16） |
| 「加入」总落在该货号第一行 | 同一张单同货号放不进两个仓（PB-U8；现在一单一仓，影响变小） |
| 改已保存草稿时的分店完整余量 | 只能加回本单原有的量（PB-U9） |
| 单价 / 单头按历史预填 | spec 有设计取值（PB-V11），**编辑器未实现** |
| 登录与权限 | 现在是开发态身份下拉，任何人可以任意身份真下单（PB-D15，负责人已接受风险，M2 接 RBAC） |

## 10. 给设计的边界

### 可以自由设计

- 版面结构、信息层级、组件形态（表格 / 卡片 / 分步 / 抽屉…）、导航方式、空状态与加载态的样子
- 编辑器左右栏的组织方式（例如按记录、按货号、按店）、明细的编辑方式
- 处理区、调用记录、状态记录的呈现方式
- 首页各区块的排布与密度

### 不能动（领域约束，不是审美）

| 约束 | 来源 |
|---|---|
| **本地状态与领星状态并排，不合成一个**；不一致本身是信号 | `10` 原则二 · 架构铁律 3 |
| 量与态分开显示，**不合成「完成率」之类的数** | `10` 原则一 · 三 |
| **⛔ 不可逆动作长得不一样**，与普通按钮分开，有确认，确认里列出将要产生的全部内容 | `10` 原则四 |
| 闸失败**点名**是哪一道、哪一行 | `10` 原则五 |
| **被丢掉的东西看得见**：过滤掉的记录给计数（折叠），列不出的带来的记录点名原因 | `10` 原则六 |
| **陈旧数据要标注**：领星状态永远带读回时间；读回失败照显上次结果并写明 | `10` 原则七 |
| **空 ≠ 0**：未知写未知 | CLAUDE.md |
| 结果未知时**不许再点下单**，只能等调用记录落定 | 出站 #2 |
| 编辑器的进入条件（§5.2，失败即关闭） | PoRoute |
| 界面文案只写**当场发生的事**（状态、结果、错误、下一步）；说明一律进折叠区、默认收起 —— **屏幕给数据，文档给论证** | CLAUDE.md · `10` §0.4 |
| 不引 UI 组件库；用现有设计系统「供应链工作台」/ 墨迹语言（`web/src/styles/`） | `10` §0.1 · §3.0 |
| 前端只打 `api/ui/`；不在前端做判据（闸、额度、状态推导都由后端给） | `10` §0.3 · `05` |
