# 计划再提交 · 提交结果显示 · 采购入口 —— 设计

> 来源：负责人 2026-10-09 试用反馈（截图：提交结果 10 条红色「跳过」；采购界面「完全看不懂，到底是怎么和已经确认的采购计划产生关联的」）。
> 下列 **负责人裁定** 均为对话中的选择原文；**我的裁定** 是落地时补的细节，负责人可否决。

## 0. 取证结论（2026-10-09，计划 1）

| 现象 | 事实 |
|---|---|
| 提交结果 10 条红色「跳过」 | 这 10 个货号·月**采购量为空**（`plan_purchase_cell.planned_units IS NULL`），按 `06` §1.2 逐条列出；显示成红色错误块，且文案「空或0」把空和 0 混为一谈（违反 CLAUDE.md「空 ≠ 0」） |
| 铸出量 | 与表一致，**不是 bug**（负责人确认「我搞错了」） |
| 旧记录被作废 | rev3、rev4 均由负责人手动「撤销这一版」（理由 `11`、`222`）后再提交 —— 因为 S-4「同一计划只许 1 版在流转」，**没有「改了直接再提交」的路**，连没变的记录（DCC1045014AI 200/100 在 rev4、rev5 完全相同）也被撤销重铸 |
| 采购看不懂 | 关联在数据里存在（采购明细的来源 = 计划记录·店·量），但界面从不说「这些来自销售计划 rev N」，计划页也没有去采购的路 |

## 1. 负责人裁定

| # | 问题 | 裁定（原文选项） |
|---|---|---|
| R1 | 没填采购量的月份，提交结果怎么显示 | 「一行灰字计数，明细折叠」：只有「填了采购量却铸不出」才用红色；空和 0 分开说 |
| R2 | 改了计划要重新提交 | 「直接再提交，没变的保留」：不用先撤销；只有变了的货号·月才替换，没变的记录原样保留（已组进采购单的不会被打断）；已下单的记录不许被再提交改动 |
| R3 | 采购员从哪里开始做采购单 | 「采购首页先列待采购记录」：第一屏是「销售计划已提交、待采购」的记录清单（计划号 · rev · 货号 · 月份 · 量 · 各店），勾选几条 →「用这些建采购单」 |

## 2. 再提交（R2）

**不变量不动**：同一计划任一时刻只有一组活记录（S-4 的理由「多版并存会让承重墙求和翻倍」继续成立）。做法是再提交时**在同一事务里**把上一版的活记录逐条处理完，再立新版：

按 `(货号, 月)` 对比「上一版的活记录」与「这次能铸出的」：

| 情形 | 判定 | 动作 |
|---|---|---|
| 没变 | `total_units` 与 `demand_by_seller` 都相同 | ★ **保留原记录**（同一 `line_id`，状态不动），归入新版；事件留痕 `carry:{plan}#{rev}` |
| 变了 | 任一不同 | 旧记录 → 已撤销（理由「被 rev N 替换」，`src = resubmit:{plan}#{rev}`）；铸新记录 |
| 新增 | 上一版没有 | 铸新记录 |
| 去掉 | 这次铸不出 | 旧记录 → 已撤销（理由「rev N 不再包含」） |

**我的裁定（可否决）**

- **D1** 「变了 / 去掉」的那条旧记录若已被采购单引用（任何未作废采购单的来源里有它，含草稿），或状态已到 已确认 / 已下单 及之后 → **整次再提交拒绝**，409 `lines_in_purchase`，逐条点名：货号 · 月 · 记录号 · 状态 · 引用它的采购单号。理由：R2「已下单的不许被改动」；草稿里的来源被静默撤销会让下单前检查才炸（`sources_orderable`），晚且远。处置：先从采购单里移掉，或保持该货号·月不变。
- **D2** 「没变」判定包含分店拆分：`demand_by_seller` 变了也算变 —— 分店占比决定采购上限，带着旧上限的记录不能冒充新的。
- **D3** 自动撤销**不是**人直接指定状态的「撤销」（`04` §2「只有撤销是手动的」）：它是「再提交」这个人的动作的后果，事件表照样记 actor + 理由 + src，可追。`04` 补一行说明。
- **D4** 「撤销这一版」照旧可用（管理员、理由必填），不再是再提交的前置步骤。
- **D5** 响应与提交结果页给四个数：保留 N · 替换 N · 新增 N · 去掉 N，并列出替换/去掉的明细（折叠）。

## 3. 提交结果显示（R1）

- `plan_submit_skip.reason` 拆开：`empty_purchase`（采购量为空 —— 没打算采购）与 `zero_purchase`（填了 0）。迁移加值（`00` S-14「新原因 → 加值走迁移」）。
- 结果页：
  - 「采购量为空」「采购量为 0」各一行**灰字计数**，明细进 `<Fold>`，默认收起。
  - 红色只给 `no_claimed_msku`（填了采购量却没有可落的 msku —— 真正铸不出）。
- 文案不再出现「空或0」。

## 4. 采购入口（R3）

采购首页（`/purchase`）第一屏改为 **待采购记录**：

```
待采购（销售计划已提交、还没组满的记录）                      [用选中的 N 条建采购单]
☐  计划 1 · rev5   DCC1045014AI   2026-10   200 件   还可组 200   A4Pet-BS-US-US 100(占比 100%)
☐  计划 1 · rev5   DCC1041294BW   2026-10   150 件   还可组 150   ⚠ 无分店依据（店铺期望销量待填）—— 不能组单
───────────────────────────────────────────
采购单（草稿 / 已下单 …）  ← 原首页列表下移
```

- 数据：`GET /v1/plan-lines?orderable=1`（已有），按计划·rev·货号·月排；无分店依据的置灰并点名原因（不是隐藏）。
- 勾选 →「用选中的 N 条建采购单」→ 进编辑器 `/purchase/new?lines=11,12`，左栏只列这几条且默认展开，**顶部写明来源**：「来自 销售计划 1 · rev5 的 2 条记录」。
- 编辑器右栏每条采购明细显示来源链：`计划1·rev5·DCC1045014AI·2026-10 → A4Pet-BS-US-US 100 件`。
- 销售计划页的提交结果加一个链接「去采购（N 条待采购）」→ `/purchase`（同一份清单，不另做入口；R3 只要求首页）。
