## 1. 原理流程

```
… 本地仓入库 → 备货表 → [ 出库/调拨 → 海外仓备货单 & 平台仓货件
   → 头程发货单 → 海外仓到货上架 & 平台仓上架 ] → 销售订单 → 终端客户
```

---

## 2. 海外仓 / 自建仓（头程）—— 本地仓 → 海外

```
CreateInbound(s_wid 本地仓 → r_wid 海外仓, product_list, logistics_id)
  → overseaStockOrderAllocate   锁库存（30 待配货 → 40 待发货）
  → packing                     上传装箱信息
  → productLabel / packageLabel 打第三方仓 SKU 标签、箱唛
  → SendInbound                 ★ 扣减发货仓库存（→ 50 待收货）
  → inboundBatchesReceipt       分批收货
  → inboundCompleteReceipt      结束到货（→ 60 已完成）
```

★ **全程没有地址，两端都是 `wid`。** 三方 API 仓另有「申报」环节
（`overseas_type`；`CreateInbound` 文档注明「提交到待发货状态为未申报状态」）。

## 3. FBA —— 亚马逊指定目的地

### 亚马逊侧（`/amzStaServer/` 透传 SP-API）

```
CreateSTATask (createInboundPlan)        提交发货地址 + 商品 + 申报量
  → ListPackingGroupItems                拿包装组
  → SubPackingInformation                ★ 提交装箱 → is_uploaded_box=1
  → GenerateShipmentPlan                 亚马逊算分仓
  → ConfirmShipmentPlan                  ★ 货件诞生 → shipment_id + ship_to + FC
  → GenerateTransportList / GetTransportList          选承运
  → GenerateDeliveryDateList / SubDeliveryTime        选送达时段
  → UpdateShipmentTrack                  ★ 跟踪号(SPD) 或 BOL+运单号(LTL)
  → printFbaLabels / printFnskuLabels    箱唛 + FNSKU 标签
  → SynchronizeSTATask                   同步回 ERP
```

### 领星侧（`/erp/` 本地记账）

```
createReadySendOrder / CreateSendedOrder   建头程发货单，list[].shipment_id 挂货件
  → SendGoods                              ★ 扣减发货仓库存
```

★ **两侧唯一纽带 = `shipment_id`**。实测
`lingxing_shipment_list_items.shipment_id` → `lingxing_fba_shipment_list.shipment_id`
**392 / 392 = 100% 命中**，链路是通的。

## 4. 客户收货 —— 两条链，按**谁履约**拆，不能混

### A · 海外仓 / 自建仓 → 终端客户（FBM / 自发货，我们自己履约）

```
平台订单同步进 ERP（订单管理「待审核发货」）
  → PreShipment   预发货（global_order_no[]）
  → BatchReview   ★ 审核发货 → 生成销售出库单 WO…

WmsOrderList / WmsOrderDetail                查单与拣货明细
  → setOrderPackageSize                      设置包裹长宽高（wo_number 必填）
  → 〔仓库物流下单〕 logistics_status 2 待下单 → 3 下单中 → 5 完成
                    （海外仓分支：6 待海外仓下单 → 7 海外仓下单中）
  → setTrackingNo   ★ 回写 waybill_no（必填）+ tracking_no + 运费 + 币种 + 计费重
  → getWmsLogisticsLabels                    取面单 PDF
  → 〔拣货 / 打包 / 交运〕 status 1 → 2 待出库 → 3 已出库（4 已截单 = 异常）

无 WMS 的自发货单另一条：
  → selfShipmentOrderDeliveryGoods           ★ 标记出库，扣库存（上限 100 单）
```

★ **扣库存时刻 = 审核发货生成 WO / `selfShipmentOrderDeliveryGoods`** ——
扣的是**海外仓库存**，不是头程那种「发货仓扣减」。

### B · FBA / 平台仓 → 终端客户（亚马逊代发，**我们无操作接口**）

```
平台订单产生 → 亚马逊自动履约（全在 Amazon 侧）
数据回流：amazon_sp_api_orders · amazon_sp_api_report_fba_shipments
          lingxing_multiplatform_order_manage_list / platform_order_list
```

★ 这一段**没有「出库单」这个单据**，也没有任何领星写接口 ——
只有订单与发货报表，**不存在可操作的流程节点**。

## 6. ★★ 三条容易搞错的地方

| # | 坑 |
|---|---|
| 1 | ★ `lingxing_warehouse_wms_order_list` 是「**海外仓发给终端客户**」，**不是入库层、不是头程**。名字里的「出库」与本地仓出库单 `lingxing_warehouse_outbound_list`（OB…）是**两件事** |
| 2 | ★ **运费两列币种不同，直接相减必错**：`logistics_estimated_freight` → **CNY**，`logistics_freight` → **USD**。且「上传面单渠道」**8,436 单两列全空**（面单由平台/客户提供，领星不经手下单）—— ★ 这是**结构性的，不是缺采** |
| 3 | ★★ **FBA 可以从海外仓发头程** —— 实测 **364 张发货单里 14 张由 `30-LA自有海外仓CHI-CA` 发出**。⇒ 海外仓既是备货单的**终点**，也可能是头程发货单的**起点**，★ **不能靠 `wid` 区分链路分支** |

★ 第 3 条对我们的影响最大：`14` 的四段管道是
`生产中 → 本地仓在库 → 排货中 → 货运中`，**没有「海外仓在库」这一段** ——
而海外仓既出头程（14/364）又出 FBM（24,045 单，扣海外仓库存）。
那批货**不在任何一段里**。

## 7. ★ 两处不确定性（作者自标，实施前必须实调）

| # | 不确定 | 怎么来的 |
|---|---|---|
| 1 | A 支「仓库物流下单」那一步（`logistics_status` 2→3→5） | ★ **文档没有单独接口**，是从 `WmsOrderList` 的状态枚举**反推**的顺序 |
| 2 | `setTrackingNo` 与 `setOrderPackageSize` 的先后 | ★ **文档没明写**，按业务逻辑排的（先量尺寸才能下单，下完单才有运单号） |

★ 记在这里而不是当成事实：**反推出来的顺序没人能证伪**，
而下游一旦按它写编排，错的那一版会一路跑到上线。
