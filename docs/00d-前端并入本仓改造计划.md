## 2. ★★ 移植风险：`store.js` 的预测核心

老原型的 `assets/store.js` 里有**逐格对上负责人 Excel** 的预测核心
（`forecastSku` 四段管道 + 两遍分配），`test_forecast.js` 是它的对账门禁。
★ **那是整个模型的信任基础** —— 换栈意味着它要从 JS 搬到 TS。

| | |
|---|---|
| ★ 判据 | 移植**不算完成**，除非有一份与 `test_forecast.js` 等价的对账测试，**逐格对上同一组数** |
| 为什么 | 「看起来对」和「逐格相同」差 23% 那种量级的偏差都可能看不出来 —— 旧项目的 228/228 门禁就是为此存在 |
| 顺序 | ★ **先搬核心 + 对账测试，再搬界面**。界面先用 `mock` 喂假数据也能跑 |

★ 墨迹设计系统 `shell.css` 是**纯 CSS，与框架无关** —— 原样带过去，不重画。

## 3. ★ 已知风险：认证暂不做（Q-5）

不是「以后再说」，是**记在案的风险**：

| 风险 | 后果 |
|---|---|
| ★ 留痕可伪造 | 前端下拉里选谁就写谁 —— 「这张不可逆的单是谁投的」**查不到人** |
| ★ 不可逆操作无主 | `confirmPlacementOption` / `SendInbound` / `SendGoods` 都不可逆，而按钮谁都能点 |

### ★ 触发重新裁定的条件（任一命中就必须回头做认证）

```
① 服务暴露到内网之外
② 供应链之外的团队开始使用
③ 出现第一次「这单是谁下的」查不清的事故
④ 审计 / 合规提出要求
```

★ 写下触发条件，是为了让「暂不做」有**失效的那一天** ——
否则它会变成一条没人再审的默认设置。
